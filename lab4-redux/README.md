# Лабораторная работа № 4 — Архитектурный паттерн Redux

Самостоятельное приложение React + Redux Toolkit, расположенное в папке `lab4-redux`, чтобы не изменять реализации предыдущих лабораторных работ.

## Реализованные требования методички

- Redux store создан через `configureStore` из `@reduxjs/toolkit`.
- Два независимых слайса: `products` и `tasks`.
- CRUD для обоих слайсов: добавление, чтение через селекторы, изменение и удаление.
- Валидация обязательных полей, цены и целочисленного количества; сообщения об ошибках хранятся в Redux.
- React-компоненты списков и форм создания/редактирования.
- Поиск и сортировка каталога по названию и цене; фильтрация списка задач.
- `useSelector` и `useDispatch` для доступа к Redux.
- React Router: обзор, каталог, задачи и обработка неизвестного маршрута.
- Локализация RU/EN с `i18next` и `react-i18next`.
- Адаптивная верстка для узких и широких экранов, без jQuery.
- Читаемые JSX-компоненты и семантические формы.

## Запуск

Требуется Node.js с npm.

```bash
cd lab4-redux
npm install
npm run dev
```

Проверка production-сборки:

```bash
npm run build
npm run preview
```

## Проверочный сценарий

1. Откройте приложение в актуальном Google Chrome.
2. В каталоге добавьте товар; попробуйте отправить пустое название и отрицательную цену.
3. Отредактируйте товар, проверьте поиск и сортировку, удалите товар.
4. В разделе задач добавьте задачу, переключите её статус и удалите.
5. Переключите язык RU/EN и проверьте маршруты.
6. Проверьте ширины 320 px, 768 px и desktop; затем повторите визуальную проверку в Firefox/Edge.

## Примечание

Проверка браузеров должна выполняться локально в реальных браузерах. Успешная сборка сама по себе не подтверждает фактическую кроссбраузерную визуальную проверку.
